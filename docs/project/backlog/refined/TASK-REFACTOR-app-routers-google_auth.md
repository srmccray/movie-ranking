# TASK-REFACTOR-app-routers-google_auth: app/routers/google_auth.py: split into a package of modules under 500 lines

## Summary
`app/routers/google_auth.py` holds the Google OAuth login, callback and account-linking endpoints plus the state-token and Google token helpers in one 706-line module, which exceeds the ADR-0002 limit (<500 lines). Split it into a package without changing any route, status code or response.

Priority: P2. Provenance: Originally generated by `spec-ops health --generate-refactor-tasks` on 2026-10-13; blueprint rewritten by hand on 2026-10-13 after checking the real file structure (the generated blueprint was not usable: wrong symbols, Python-style outputs for CSS/TSX, or sub-modules over the limit).

## Target Decomposition
Convert the module into the package `app/routers/google_auth/`. `app/main.py` keeps working unchanged (`from app.routers import google_auth` and `google_auth.router`) because `__init__.py` re-exports `router`.

## Decomposition Blueprint
Current size: 706 lines (`wc -l app/routers/google_auth.py`, matches `.specops/grandfathered_debt.json`).
Current structure (line numbers from the current file):
- Imports, `logger`, `router = APIRouter(tags=["auth"])`, `GOOGLE_AUTH_URL`, `GOOGLE_TOKEN_URL`, `STATE_EXPIRATION_MINUTES`: lines 1-34.
- OAuth helpers: `_cleanup_expired_states` (37-44), `_create_state_token` (47-84), `_validate_state_token` (87-115), `_exchange_code_for_tokens` (118-150), `_verify_google_id_token` (153-184, synchronous), `_handle_link_callback` (187-284).
- Endpoints: `google_login` GET `/google/login/` (287-341), `google_callback` GET `/google/callback/` (344-483), `google_link` GET `/google/link/` (486-557), `google_link_callback` GET `/google/link/callback/` (560-706).

Proposed modules in `app/routers/google_auth/`:
- `oauth.py` (about 190 lines): constants, `_cleanup_expired_states`, `_create_state_token`, `_validate_state_token`, `_exchange_code_for_tokens`, `_verify_google_id_token`. No router.
- `login.py` (about 215 lines): its own `router`, `google_login` and `google_callback`.
- `link.py` (about 330 lines): its own `router`, `_handle_link_callback`, `google_link` and `google_link_callback`.
- `__init__.py` (about 15 lines): `router = APIRouter(tags=["auth"])`, `router.include_router(login.router)`, `router.include_router(link.router)`; keep the four paths exactly as they are (`/google/login/`, `/google/callback/`, `/google/link/`, `/google/link/callback/`, all with trailing slashes).

## Notes and Risks
- Test patch targets: `tests/test_google_auth.py` patches `app.routers.google_auth._verify_google_id_token` (11 sites) and `app.routers.google_auth._exchange_code_for_tokens` (11 sites). A patch only takes effect on the module whose code looks the name up, so after the split `login.py` and `link.py` must call these helpers as `oauth._verify_google_id_token(...)` / `oauth._exchange_code_for_tokens(...)` (module attribute access, not `from .oauth import ...`), and the test patch strings must change to `app.routers.google_auth.oauth._verify_google_id_token` and `app.routers.google_auth.oauth._exchange_code_for_tokens`. Coordinate with TASK-REFACTOR-tests-test_google_auth, which moves those tests.
- Do not add a barrel that re-exports the private `_` helpers; only `router` is public.
- Keep every route path with its trailing slash (project convention).
