# TASK-REFACTOR-tests-test_google_auth: tests/test_google_auth.py: split into two test modules under 500 lines

## Summary
`tests/test_google_auth.py` (649 lines, 28 tests) covers Google OAuth login/callback, the end-to-end OAuth flow, password behavior for Google users, the profile endpoint and account linking in one file.

Priority: P2. Provenance: Originally generated by `spec-ops health --generate-refactor-tasks` on 2026-10-13; blueprint rewritten by hand on 2026-10-13 after checking the real file structure (the generated blueprint was not usable: wrong symbols, Python-style outputs for CSS/TSX, or sub-modules over the limit).

## Target Decomposition
Split into sibling modules in `tests/` (no package and no barrel re-exports).

## Decomposition Blueprint
Current size: 649 lines (`wc -l tests/test_google_auth.py`, matches `.specops/grandfathered_debt.json`).
Current classes (line numbers from the current file; imports at lines 11-15): `TestGoogleLoginEndpoint` (18-64), `TestGoogleCallbackEndpoint` (67-119), `TestGoogleOAuthFlow` (122-273), `TestGoogleUserCanStillUsePassword` (276-313), `TestGoogleOnlyUserCannotUsePassword` (316-353), `TestUserProfileEndpoint` (356-392), `TestGoogleLinkEndpoint` (395-474), `TestGoogleLinkCallbackEndpoint` (477-649).

Proposed modules:
- `tests/test_google_auth_login.py` (about 270 lines): `TestGoogleLoginEndpoint`, `TestGoogleCallbackEndpoint`, `TestGoogleOAuthFlow`.
- `tests/test_google_auth_accounts.py` (about 390 lines): `TestGoogleUserCanStillUsePassword`, `TestGoogleOnlyUserCannotUsePassword`, `TestUserProfileEndpoint`, `TestGoogleLinkEndpoint`, `TestGoogleLinkCallbackEndpoint`.
Both modules need the shared imports (`datetime`, `AsyncMock`/`MagicMock`/`patch`, `pytest`, `AsyncClient`).

## Notes and Risks
The tests patch `app.routers.google_auth._verify_google_id_token` (11 sites) and `app.routers.google_auth._exchange_code_for_tokens` (11 sites). If TASK-REFACTOR-app-routers-google_auth lands first, these strings must be updated to the new `app.routers.google_auth.oauth.*` location; if this task lands first, no change is needed. Do the two tasks in either order but update the strings in whichever lands second.
