# TASK-REFACTOR-frontend-__tests__-mocks-handlers: frontend/src/__tests__/mocks/handlers.ts: split into a handlers/ directory under 500 lines per file

## Summary
`frontend/src/__tests__/mocks/handlers.ts` holds every MSW mock handler (auth, Google OAuth, movies, rankings, analytics, Amazon Prime import), the mutable mock state and the reset/setter helpers in one 894-line file.

Priority: P2. Provenance: Originally generated by `spec-ops health --generate-refactor-tasks` on 2026-10-13; blueprint rewritten by hand on 2026-10-13 after checking the real file structure (the generated blueprint was not usable: wrong symbols, Python-style outputs for CSS/TSX, or sub-modules over the limit).

## Target Decomposition
Replace the file with the directory `frontend/src/__tests__/mocks/handlers/` and an `index.ts`. Existing imports such as `from '../__tests__/mocks/handlers'` and `from './handlers'` in `server.ts` keep resolving to `handlers/index.ts`, so no test file needs to change. The old `handlers.ts` must be deleted so the file and the directory do not collide.

## Decomposition Blueprint
Current size: 894 lines (`wc -l frontend/src/__tests__/mocks/handlers.ts`, matches `.specops/grandfathered_debt.json`).
Current structure (line numbers from the current file):
- Imports and constants/state: lines 10-82 (`MOCK_TOKEN`, `MOCK_USER_EMAIL`, `MOCK_USER_PASSWORD`, `MOCK_TMDB_RESULTS`, `registeredUsers`, `MOCK_GOOGLE_STATE`, `MOCK_GOOGLE_AUTH_URL`, `validOAuthStates`, `validLinkStates`, `userHasGoogleLinked`, `movies`, `rankings`, `tmdbServiceError`).
- `export const handlers = [...]` (84-525): `POST /api/v1/auth/register` (86), `POST /auth/login` (127), `GET /movies/search/` (174), `POST /movies/` (242), `POST /rankings/` (281), `GET /rankings/` (322), `GET /analytics/stats/` (359), `GET /analytics/rating-distribution/` (391), `GET /auth/google/login/` (425), `GET /auth/google/callback/` (436), `GET /auth/me/` (477), `GET /auth/google/link/` (498).
- State helpers: `resetMockData` (527), `setTmdbServiceError` (541), `addValidOAuthState` (546), `setUserGoogleLinked` (551).
- Import section (555-894): `MockImportSession` interface (560), `importSessions` (591), `MOCK_IMPORT_SESSION` (594), `importHandlers` (658-875: upload, get session, add, skip, delete), `resetImportSessions` (877), `createMockImportSession` (882), and the final `export { ... }` (894).

Proposed files in `handlers/`:
- `state.ts` (about 100 lines): the constants and mutable state, plus `resetMockData`, `setTmdbServiceError`, `addValidOAuthState`, `setUserGoogleLinked`. Keep the `let` variables (`userHasGoogleLinked`, `tmdbServiceError`) and the functions that reassign them in this one file, because other modules can read an ES-module `let` export but cannot assign it.
- `auth.ts` (about 190 lines): `authHandlers` = register, login, Google login/callback, `/auth/me/`, Google link.
- `movies.ts` (about 250 lines): `movieHandlers` = movies search/create, rankings create/list, analytics stats and rating distribution.
- `import.ts` (about 340 lines): `MockImportSession`, `importSessions`, `MOCK_IMPORT_SESSION`, `importHandlers`, `resetImportSessions`, `createMockImportSession`.
- `index.ts` (about 30 lines): `export const handlers = [...authHandlers, ...movieHandlers]` and re-exports of everything the old file exported (`importHandlers`, `resetMockData`, `setTmdbServiceError`, `addValidOAuthState`, `setUserGoogleLinked`, `resetImportSessions`, `createMockImportSession`, `MOCK_TOKEN`, `MOCK_USER_EMAIL`, `MOCK_USER_PASSWORD`, `MOCK_TMDB_RESULTS`, `MOCK_GOOGLE_STATE`, `MOCK_GOOGLE_AUTH_URL`, `MOCK_IMPORT_SESSION`).

## Notes and Risks
- Importers of the module (must keep working): `api/client.test.ts`, `context/AuthContext.test.tsx`, `components/MovieSearch.test.tsx`, `components/ProtectedRoute.test.tsx`, `__tests__/SettingsPage.test.tsx`, `__tests__/mocks/server.ts`, `pages/LoginPage.test.tsx`, `pages/RegisterPage.test.tsx`, `pages/GoogleCallbackPage.test.tsx`.
- Preserve handler order when concatenating (MSW matches the first handler); the paths listed above are all distinct, so order only matters if a new overlapping path is added.
- The mock set has no handler for the PATCH `.../match/` endpoint (PRD-0002); that is a separate gap and is out of scope here.
- The file's top-of-file doc comment should move to `handlers/index.ts`.
